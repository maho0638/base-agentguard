# OpenAI Maintainer Evidence Pack

OpenAI's Codex for Open Source program is strongest when the repository shows
real maintenance work, not just a one-time demo.

## Evidence to create before applying

- Public repository with MIT license.
- Working demo URL.
- Clear README with setup, safety posture, roadmap, and Base docs links.
- At least 5 meaningful issues:
  - x402 review flow
  - Builder Code attribution
  - Base Sepolia proof deployment
  - EIP-712 typed data review
  - risk-rule tests
- At least 1 release tag, such as `v0.1.0`.
- At least 1 merged pull request, even if it is a docs/rules improvement.
- A short demo video or GIF linked in README.
- Impact metrics file with early usage and maintenance activity.

## API credit use case

Use API credits only for open-source maintainer workflows:

- issue triage
- pull request review
- risk-rule generation
- documentation updates
- test generation
- release notes
- security review checklists

## Do not claim

- guaranteed OpenAI approval
- guaranteed Base airdrop
- guaranteed user safety
- live transaction execution if the app only prepares receipts
- audit status before an audit exists
